# SM crypto Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Provide an interoperable Java Starter and browser client for selected JSON endpoints.

**Architecture:** Protocol primitives wrap Bouncy Castle and a browser crypto library. The server integrates at the MVC servlet boundary. The browser fetches the active public key and uses a new independent key pair per exchange.

**Tech Stack:** Java 8 bytecode; Spring Boot MVC 2.x; Bouncy Castle; JUnit 5; JavaScript ES modules.

**Spec:** ../specs/2026-11-16-sm-crypto-design.md

## Global Constraints

No cleartext fallback, no private keys in Git, no substitutions for TLS or authorization, no implicit global encryption. Require authenticated envelopes and replay rejection.

## Review Focus

Test tampering with tags and route metadata, expired requests, duplicates, business errors, malformed envelopes, and actual browser/Java wire compatibility. Build on JDK 8/11/17/21.
